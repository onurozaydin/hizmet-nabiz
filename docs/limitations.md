# Limitations and next improvements

## Current limitations

- One winter week is a focused cohort, not a seasonally representative annual benchmark.
- Community Board volume is not population-normalized and does not measure unmet need.
- Peer matching covers agency and problem type, but not severity, weather, staffing, inspection
  complexity, repeat reports, or policy changes.
- Closure timestamps are administrative outcomes and may not equal resident-perceived resolution.
- The capacity scenario uses an assumed effect; it is not a forecast or causal estimate.
- The portable dashboard filters its priority table by borough but is a snapshot, not a live feed.

## Next improvements

1. Add four seasonally stratified windows and a sensitivity analysis for peer thresholds.
2. Join official Community District population denominators with explicit join coverage QA.
3. Evaluate hierarchical models with partial pooling across problem types and boards.
4. Design a randomized or stepped-wedge intervention to estimate the real effect of case review.
5. Add immutable SHA pins and hash-locked Python dependencies for a stricter supply-chain posture.
